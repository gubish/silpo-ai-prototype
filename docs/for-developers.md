# МГ: що передаємо розробці

Оновлено: 2026-10-08

Короткий вхід для команди, яка робитиме справжнього МГ на LLM. Прототип показує поведінку, правила її описують, а для моделі ще треба зібрати кілька речей нижче.

## Що ще треба зібрати для LLM

1. **Специфікації сценаріїв** — для кожного: кроки, стани, потрібні дані, крайові випадки (зараз розкидано між правилами й кодом).
2. **Розподіл «модель / код».** Модель — тексти, вибір товарів із поясненням, одне питання, припущення, чіпси. Код (бекенд) — ціни й суми, мінімальне замовлення й пороги доставки, підбір «що докласти», дії з кошиком і «Скасувати». У прототипі це вже детермінована логіка — моделі не віддаємо.
3. **Інструменти (tools)** — з чого модель бере факти: `catalog.search`, `product.get`, `cart.get`, `recipes.search`, `orders.history` (назви — пропозиція, узгоджує розробка).
4. **JSON-схема відповіді** для structured output: `intro`, `assumptions`, `items`, `list`, `advice`, `chips`, `cart_action` (чернетка — в інструкції для моделі).
5. **Приклади діалогів (few-shot)** — 1–2 на сценарій, записані з прототипу.
6. **Тестовий набір** — чекліст із правил як критерії для моделі-судді; ті самі приклади — для донавчання.

## Відкриті питання

- Алкоголь: правила 18+ погоджують юристи.
- Кризові відповіді: номери гарячих ліній і формулювання погоджує Сільпо.
- Посилання на месенджери підтримки (Telegram, Viber, Messenger) — у прототипі заглушки.
- Репозиторій прототипу публічний — чи можна тримати правила відкритими.
